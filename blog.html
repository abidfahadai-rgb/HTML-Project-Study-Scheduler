Project Plan and Troubleshooting Log

The plan that guided the build, and the bugs that tested it.

Why Agile?

The Agile methodology, from the Agile Manifesto of 2001, values adaptive planning, frequent delivery, and continual feedback over rigid up-front specification. Even for a solo three-week project, several Agile practices were helpful:

  • Weekly sprints - splitting the build into one-week iterations meant each week ended with a working product instead of one panicked final push.
  • Working software first - the login flow was built and tested before writing about it.
  • Responding to change - the task model gained a priority field mid-project because sorting by date alone was not enough.
  • Retrospectives - each sprint ended with a short note in the README about what to improve.

Troubleshooting Log

Bug #1 - Same-day tasks marked as overdue

Encountered: 04 November 2025 at 21:14

Tasks added with today's date were appearing in the list immediately marked as overdue and shown in red, even though their deadline had not yet passed.

Failing screenshot

[ Screenshot: task "Read Chapter 4" with due date today showing in red as overdue, even though it is not overdue ]

Code that caused the issue

// Original buggy isOverdue function
function isOverdue(task) {
    if (task.completed === true) {
        return false;
    }
    // PROBLEM: This compares the full timestamp.
    // "Today at 00:00" is always less than "now",
    // so today's tasks appear overdue.
    var dueDate = new Date(task.date);
    if (dueDate < new Date()) {
        return true;
    }
    return false;
}

Resolution

Resolved: 04 November 2025 at 22:02
[ Screenshot: same task now showing normally with no overdue styling on its due date ]

Corrected code

// Fixed isOverdue - both dates compared at start of day
function isOverdue(task) {
    if (task.completed === true) {
        return false;
    }
    var today = new Date();
    today.setHours(0, 0, 0, 0);  // reset time to midnight
    var dueDate = new Date(task.date);
    if (dueDate < today) {
        return true;
    }
    return false;
}

Explanation

The original comparison used new Date() on the right side, which returns the current moment in time. But new Date(task.date) on the left side made a date at midnight (start of the day). Since midnight is always earlier than the current time, every task created on its due day looked overdue.

The fix was to call setHours(0, 0, 0, 0) on the "today" date so both sides are compared at the start of the day. I learned about this from the MDN documentation on the JavaScript Date object.

Bug #2 - Tasks from one account showing for another

Encountered: 09 November 2025 at 15:38

When I created two test accounts in the same browser, the tasks from the first account appeared in the second account's task list. This was a data privacy issue.

Failing screenshot

[ Screenshot: account "alice" signed in, but showing three tasks that were originally created under "bob" ]

Code that caused the issue

// Original buggy getMyTasks - returned ALL tasks
function getMyTasks() {
    return getAllTasks();  // BUG: no filtering by owner
}

// Original createTask had no owner field
function createTask(data) {
    var allTasks = getAllTasks();
    var newTask = {
        id: "task_" + Date.now(),
        title: data.title
        // ... rest of fields, but no owner!
    };
    allTasks.push(newTask);
    saveAllTasks(allTasks);
}

Resolution

Resolved: 09 November 2025 at 16:21
[ Screenshot: account "alice" now sees an empty task list, while bob's tasks remain visible only to him ]

Corrected code

// Fixed getMyTasks - filters by logged-in user
function getMyTasks() {
    var user = getCurrentUser();
    var all = getAllTasks();
    var mine = [];
    for (var i = 0; i < all.length; i++) {
        if (all[i].owner === user) {
            mine.push(all[i]);
        }
    }
    return mine;
}

// Fixed createTask - stamps owner on every new task
var newTask = {
    id: "task_" + Date.now(),
    owner: getCurrentUser(),  // FIX: save who made it
    title: title,
    // ... other fields
};

Explanation

The problem was simple: I was storing all tasks in one big list with no way to know who owned which task. localStorage is shared across the whole site, so everyone saw the same list.

The fix was to add an owner field to each task when it is created, and then filter by that field when reading. I read about user data isolation on the MDN page about Web Storage. I also added this as an example on the Ethics page to show why login-based isolation matters.
